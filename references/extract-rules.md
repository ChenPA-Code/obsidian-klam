# 提取规则：什么算「有长期价值的内容」

核心判定原则：**这条内容未来还会被查阅 / 会被执行 / 会被复用吗？** 会 → 写入；不会 → 丢弃。
分类是辅助组织手段，**不是硬性模板**——对话是什么样就按什么样整理，允许混合、允许缺省、允许新增小节。

## 常见内容形态（按需组合，不强制全部出现）

| 形态 | 示例 | 对应小节 |
|---|---|---|
| 决定与结论 | 「就用方案 A」「项目名定为 X」 | `## 关键决定` |
| 行动项与待办 | 「下周前发我」「你搭 M2 脚本」 | `## 行动项`（`- [ ]`） |
| 学习要点/新知 | 「增量学习就是只更新新数据的参数」 | `## 学习要点` |
| 事实与背景 | 「vault 有 1200 条笔记」 | `## 背景与事实` |
| 资料与链接 | 文献、URL、文件路径 | `## 资料与链接` |
| 灵感与想法 | 「也许可以做个自动归档脚本」 | `## 灵感与想法` |
| 待讨论问题 | 「还不确定用 CLI 还是直写」 | `## 待讨论问题` |
| 产出物 | 「生成了 report.pdf，路径 /out/」 | `## 产出物` |
| 原话摘录 | 值得原样保留的用户表达 | `## 原话摘录` |

组织原则：
- 先判断对话性质（学习 / 工作整理 / 资料收集 / 聊天要点 / 混合），选 2~5 个最贴切的小节，**不强行凑满四段**。
- 一条内容可以同时属于多个小节（如"决定"里含"行动项"），取最贴切的位置，避免重复。
- 对话中有而模块库里没有的形态，允许自建小节（如 `## 学习计划`、`## 素材清单`）。

## 不写（噪音）

- 寒暄、客套、语气词（「好的」「谢谢」「嗯嗯」）
- 过程性讨论、试错中间态、已被取代的结论
- 纯临时信息（一次性变量、随口举例）
- 重复确认（同一结论说两遍，只保留第一遍）

## 敏感（拦截，绝不写入）

- 凭证类：API key、token、密码、私钥、AK/SK、JWT
- 身份类：身份证号、手机号、银行卡号、家庭住址、健康记录
- 触发后行为：不写入任何字段；在预览清单中提示「含敏感信息 N 条，已拦截」；如用户要求脱敏，仅写入脱敏后的替身值（如 `sk-***`）。

## 标注规则（幻觉缓解）

- 每个条目尽量附**来源**：引用户原话片段（`用户原话：「……」`）或消息序号，便于人工核对。
- 对话中未直接出现、由 AI 推断的结论 → 追加「（推断）」。
- 来源不明或数字不确定 → 标注「（待核实）」。
- 无把握的内容一律不写（宁缺毋滥）。
